🌐 CORS Misconfigurations

Three API endpoints. Three different CORS configurations. All broken differently.

Use curl in your terminal to examine the response headers.

Level 1

Open Door

Endpoint: /cors/api/public-profile

How open is this API?

Easy
Hint

Use curl -v and look at the response headers. What does the Access-Control-Allow-Origin header say?

Level 2

Pattern Match

Endpoint: /cors/api/trusted-profile

The server checks your Origin. But how carefully?

Medium
Hint 1

The server checks if your Origin matches a pattern. Send different Origin headers and observe which are accepted and which are rejected.

Hint 2

String matching functions can be tricked if the check isn't precise enough. Think about domain names that share the same ending.

Level 3

Mirror Mirror

Endpoint: /cors/api/secret-profile

This endpoint requires authentication and has CORS. Both are misconfigured.

Hard
Hint 1

Send a request without any credentials. Read the error message carefully.

Hint 2

You need two things: proof of identity AND an Origin header. Look at how the server responds to your Origin — does it validate it or just repeat it?
